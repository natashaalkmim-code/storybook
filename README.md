# Storybook Studio

A single-page site for Storybook Studio (Miren Arregui) built around one
persistent 3D scene: five folder dividers cascading in depth, each hiding a
paper "sheet" that flies out to become the full page when its divider is
clicked. React 19 + Vite + GSAP, no CMS, no backend, no Tailwind.

## Quick start

```bash
npm install
npm run dev       # local dev server
npm run build      # production build -> dist/
npm run preview    # serve the production build locally, to sanity-check it
```

## How the scene works, in one paragraph

`src/config/stackConfig.js` holds three size tiers (desktop / tablet /
mobile) with every spacing, size and duration number the scene uses.
`src/config/geometry.js` turns a section index + the active tier into a
resting/edge/open transform — pure functions, no stored state, so opening
and closing never drifts. `src/components/FolderStack.jsx` is the only place
that touches GSAP: it reads those pure transforms and drives one timeline
per navigation. Routing (`/`, `/:sectionId`) just tells FolderStack which
index should be open — the 3D scene itself never remounts.

## Where to edit things

| I want to change...                          | Edit this file                    |
|-----------------------------------------------|------------------------------------|
| Section copy (About/Services/Process/Projects/Contact) | `src/data/content.js` |
| Section labels, colors, image paths            | `src/data/sections.js` |
| Divider/sheet spacing, sizes, tilt, timing, easing | `src/config/stackConfig.js` |
| The actual divider/sheet artwork                | `public/assets/dividers/*.webp`, `public/assets/sheets/*.webp` |
| Logo (optional — see below)                     | `public/assets/branding/` + `src/components/BrandHeader.jsx` |
| Colors, fonts                                   | `src/styles/global.css` (CSS custom properties at the top) |
| Divider/sheet/page visual styling                | `src/styles/stack.css`, `src/styles/pages.css` |

### Swapping in real artwork

Drop new files at:
- `public/assets/dividers/{projects,contact,about,services,process}.webp`
- `public/assets/sheets/{projects,contact,about,services,process}.webp`

Same filenames, any size — dividers render with `object-fit: contain`
(keeps the tab silhouette intact), sheets render with `object-fit: cover`
(fine to crop paper texture). If a file is missing or fails to load, each
component falls back to a flat color block instead of breaking, so you can
swap them in one at a time.

The current art is a placeholder set generated by `scripts/generate_placeholders.py`
(flat-color tab/paper shapes in the brand palette) — safe to delete once real
assets are in, kept only for provenance.

### Logo

The wordmark renders as styled text by default (`BrandHeader.jsx`) — no
image required. If you'd rather use a real logo mark, drop it at
`public/assets/branding/` and swap the SVG flourish + text block in
`BrandHeader.jsx` for an `<img>`.

### The one thing to double-check on real artwork

Divider label text color is set per section in `src/styles/stack.css`
(`--divider-label-color` inside each `.divider--<color>` rule) for
readability against the current flat-color fallback. Once real artwork is
in, check the label still reads clearly over it — adjust that variable if
not.

## Tuning the geometry

Everything lives in `src/config/stackConfig.js`. A few notes if you're
adjusting it:

- **`openZ` — keep it small.** Under a CSS `perspective`, `translateZ`
  doesn't just control stacking order, it visually *scales* the element
  (`perspective / (perspective - z)`). A large `openZ` blows the open page
  up past its intended width/height. The shipped values (70/55/35 across
  tiers) are deliberately modest — everything else already recedes via
  `edgePushX`/`edgePushZ`, so the open sheet doesn't need much forward
  travel to read as frontmost.
- **`SHEET_OFFSET_RATIO`** (in the same file) controls how far each sheet
  sits between its own divider and the next one, on both the Y and Z axis.
- **Switching sections while one is open** happens by closing (the × button
  or Esc) and clicking the next tab — the open sheet fills most of the
  viewport, which covers the other dividers by design (matches the
  reference mockup). Direct tab-to-tab switching without closing is
  possible in principle (the timeline logic already supports it — see the
  screen-reader nav below) but would need a much larger `edgePushX` to
  physically clear the open sheet, which starts to fight the "sheet fills
  most of the screen" reading experience. Left as-is; a knob worth
  revisiting if the brief changes.
- **Mobile tap targets:** on narrow screens the resting sheet is sized down
  (`sheetHeight`, not `openHeight` — that only affects the peek, not the
  opened page) specifically so each divider keeps a real uncovered strip to
  tap, not just its exact center pixel.

## Accessibility

- Dividers are real `<button>`s with `aria-expanded`/`aria-label`.
- Esc closes the open section.
- A visually-hidden `<nav>` with real links to all 5 sections sits in the
  DOM (`StorybookScene.jsx`) as an always-reachable fallback for
  keyboard/screen-reader users and for search engines — same routes
  (`/services`, `/about`, etc.) the visible dividers use.
- `prefers-reduced-motion` is respected: the CSS applies a blanket rule, and
  `FolderStack.jsx` additionally scales every GSAP timeline down to ~12% of
  its normal duration (not just disabling it) so the same choreography
  still happens, just fast.

## Deploying

`vercel.json` already has the SPA rewrite rule Vercel needs so that a
direct visit to e.g. `/services` doesn't 404 — nothing else to configure.

```bash
git init
git add .
git commit -m "Storybook Studio site"
git remote add origin <your-repo-url>
git push -u origin main
```

Then import the repo in Vercel (or run `vercel` from this folder) — it'll
detect the Vite project automatically.

## Stack

React 19 · Vite · GSAP · react-router-dom. No Tailwind, no CMS, no backend —
everything editable lives in the files listed above.
